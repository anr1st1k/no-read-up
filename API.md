# API - как сайт и сервер общаются

Все запросы начинаются с `/api`, данные передаются в JSON.
Сайт: `http://localhost:8080`, сервер напрямую: `http://localhost:8000`.

## Уровни секретности

`public` < `internal` < `confidential` < `secret`

Открыть ресурс можно, если допуск пользователя **не ниже** уровня ресурса.
Новый пользователь получает `public`.

## Вход

После входа сайт получает токен и передаёт его во всех запросах, где нужен вход:

```
Authorization: Bearer <токен>
```

## Ошибки

Любая ошибка: `{"detail": "текст для пользователя"}`.
При ошибке проверки (422) ещё и список по полям:

```json
{"detail": "Ошибка валидации",
 "errors": [{"field": "password", "message": "Пароль должен содержать цифру"}]}
```

## Запросы

| Запрос | Нужен вход | Отправляем | Получаем |
|---|---|---|---|
| `POST /api/register` | нет | `{"login", "password"}` | `201` `{"message": "user создан"}`<br>`422` неверные данные<br>`409` логин занят |
| `POST /api/login` | нет | `{"login", "password"}` | `200` `{"access_token": "...", "token_type": "bearer"}`<br>`401` неверный логин или пароль |
| `GET /api/me` | да | - | `200` `{"id", "login", "clearance", "created_at"}` |
| `GET /api/resources` | да | - | `200` список `[{"id", "title", "classification", "accessible"}]` |
| `GET /api/resources/{id}` | да | - | `200` `{"id", "title", "classification", "content"}`<br>`403` не хватает допуска<br>`404` нет такого ресурса |
| `GET /api/health` | нет | - | `200` `{"status": "ok"}` |

Без токена или с истёкшим токеном любой запрос с входом отвечает `401`.

## Правила проверки при регистрации

- **login**: 3-32 символа, латинские буквы, цифры, `.` `_` `-`
- **password**: 8-128 символов, есть заглавная и строчная латинская буква, цифра и спецсимвол

Пароль никогда не возвращается в ответах.
